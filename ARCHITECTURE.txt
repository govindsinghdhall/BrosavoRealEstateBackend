2. MULTI-TENANT SaaS MODEL
--------------------------------------------------------------------------------

  Every signup creates a NEW ORGANIZATION (tenant).

  Flow:
    1. POST /api/v1/auth/register
       Body: organizationName, firstName, lastName, email, password, phone?
    2. Backend creates Organization + unique slug
    3. Seeds default roles: admin, manager, agent, viewer
    4. Seeds default lead sources: Website, Walk-in, Referral, Social, Phone
    5. Signing-up user becomes org ADMIN
    6. JWT includes: userId, organizationId, roleId, email
    7. ALL subsequent queries are scoped by organizationId

  Isolation rule:
    - Every document stores organizationId
    - Auth middleware attaches req.auth
    - Services always filter by req.auth.organizationId


3. REQUEST LIFECYCLE
--------------------------------------------------------------------------------

  Client Request
       │
       ▼
  Helmet / CORS / Morgan / JSON body parser
       │
       ▼
  Router (/api/v1/...)
       │
       ├── Public routes (auth/register, auth/login, public/*, marketing/google/callback)
       │
       └── Protected routes
             │
             ├── authenticate()     → verify JWT, set req.auth
             ├── requirePermission()→ check role permissions
             ├── Zod validate       → request body/query
             ▼
           Controller  →  Service  →  Model / Repository
             │
             ▼
           success() / successPaginated() / AppError → errorHandler

5. API SURFACE (/api/v1)
--------------------------------------------------------------------------------

  HEALTH
    GET  /health

  AUTH
    POST /auth/register            Create org + admin user
    POST /auth/login               Email/password → JWT
    POST /auth/logout              Client clears token
    GET  /auth/me                  Session restore { userId }

  ORGANIZATION / TEAM
    /organizations/*               Tenant branding & settings
    /users/*                       Team members (per org)
    /roles/*                       RBAC roles

  CRM CORE
    /leads/*                       Lead pipeline + notes + timeline
    /contacts/*                    Contacts (+ import)
    /properties/*                  Inventory
    /property-lookups/*            Lookup values (types, cities, etc.)
    /lead-sources/*                Lead source master
    /site-visits/*                 Site visit scheduling
    /bookings/*                    Bookings
    /reports/*                     Dashboards / reports

  WHATSAPP
    GET    /whatsapp/settings
    PATCH  /whatsapp/settings      Org display settings only
    GET    /whatsapp/templates
    POST   /whatsapp/templates
    PUT    /whatsapp/templates/:id
    DELETE /whatsapp/templates/:id
    POST   /whatsapp/send          Sends via GLOBAL Meta credentials

  MARKETING HUB
    GET  /marketing/google/login          Start Google OAuth (JWT required)
    GET  /marketing/google/callback       Public OAuth callback (no JWT)
    POST /marketing/google/disconnect
    ... reviews / AI reply / content / campaigns / analytics / settings

  PUBLIC WEBSITE
    /public/*                      Listings + inquiry capture (org-scoped)


6. AUTHENTICATION & AUTHORIZATION
--------------------------------------------------------------------------------

  Auth method : JWT Bearer token
  Claims      : userId, organizationId, roleId, email
  Secret      : JWT_SECRET (env)
  Expiry      : JWT_EXPIRES_IN (default 7d)

  Roles (seeded per org):
    admin   → all permissions
    manager → most CRM + marketing read/reply (no full org manage)
    agent   → leads/contacts/visits/bookings (limited)
    viewer  → read-only

  Middleware:
    authenticate(req)            → sets req.auth or 401
    requirePermission(perm)      → 403 if role lacks permission

8. EXTERNAL INTEGRATIONS
--------------------------------------------------------------------------------

  A) WhatsApp Cloud API (Meta)
     Env:
       WHATSAPP_API_BASE_URL
       WHATSAPP_GRAPH_API_VERSION
       WHATSAPP_PHONE_NUMBER_ID      ← global (shared number)
       WHATSAPP_ACCESS_TOKEN         ← global

     Current design:
       - Templates & settings are per organization
       - Sending uses ONE shared Meta phone number / token from env
       - Per-customer WhatsApp Business accounts are NOT supported yet

  B) Google Business Profile (Marketing Hub)
     Env:
       GOOGLE_CLIENT_ID
       GOOGLE_CLIENT_SECRET
       GOOGLE_REDIRECT_URI
         → https://brisavorealestatebackend-1.onrender.com/api/v1/marketing/google/callback
       API_BASE_URL
       FRONTEND_URL
         → https://crm.durgaproperty.com

     OAuth flow:
       1. CRM calls GET /marketing/google/login (JWT)
       2. Backend builds Google auth URL with redirect_uri = production callback
       3. Google redirects to /api/v1/marketing/google/callback?code&state
       4. Backend exchanges code, stores tokens on MarketingProviderAccount
       5. Backend redirects browser to FRONTEND_URL/marketing?google=connected

     Important:
       Never build redirect URIs from localhost:PORT (Render uses PORT=10000
       internally — that caused ERR_CONNECTION_REFUSED). Use urls.ts helpers.

11. DEPLOYMENT
--------------------------------------------------------------------------------

  Platform : Render (web service)
  Config   : render.yaml
  Build    : npm install && npm run build
  Start    : npm start  (node dist/index.js)
  Health   : GET /api/v1/health

  Local Mongo (preferred for this project):
    From monorepo root:
      npm run db:up     # docker compose → Mongo :27017 + Mongo Express :8081
      npm run seed

  Local API:
    cd RealEstateBackend
    npm run dev         # typically :3000 or :4000 from .env PORT


12. CURRENT CAPABILITY SNAPSHOT
--------------------------------------------------------------------------------

  READY
    - Multi-tenant register / login / JWT scoping
    - Full CRM (leads, contacts, properties, visits, bookings, reports)
    - Role-based permissions
    - Public website feed endpoints
    - WhatsApp templates + send via shared Meta credentials
    - Marketing Hub Google OAuth + reviews/content/campaigns scaffolding

  NOT READY / LIMITATIONS
    - Per-organization WhatsApp Business credentials
      (all orgs share WHATSAPP_PHONE_NUMBER_ID / ACCESS_TOKEN)
    - Google reviews/content live API still partially stubbed in client
    - Customer cannot bring their own WhatsApp number without code changes


13. ONBOARDING A NEW CUSTOMER (TODAY)

    2. They can use leads/properties/team immediately

  Marketing / Google:
    - Customer connects Google via OAuth in Marketing Hub
    - Requires GOOGLE_* env + correct redirect URI in Google Cloud Console
